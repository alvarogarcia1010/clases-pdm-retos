Guía de instalación: React Native CLI para Android

Todo lo que hace falta para que el jueves 12 su primera app corra en un emulador o en su teléfono. Docente: Alvaro García.

Antes de empezar Windows macOS Teléfono o emulador Verificar y entregar Errores comunes
Sigan los pasos en orden y no se salten ninguno. Casi todos los problemas de una primera clase práctica vienen de instalar las cosas en otro orden, de tener dos versiones de Java, o de abrir la terminal antes de configurar las variables de entorno. Calculen entre 60 y 90 minutos más el tiempo de descarga (unos 4 GB en total). Háganlo con buena conexión y la laptop conectada a la corriente.

Antes de empezar

Vamos a instalar cuatro cosas. Conviene saber para qué sirve cada una, porque cuando algo falle van a saber dónde mirar.

Node.js (LTS, 22 o superior)Ejecuta JavaScript en su computadora. Trae npm y npx, con los que se crea y arranca el proyecto.
JDK 17El kit de Java. Android se compila con Gradle, y Gradle corre sobre Java. Tiene que ser la 17: con versiones más nuevas hay problemas.
Android Studio + SDKTrae el SDK de Android (las herramientas que compilan la app), adb (que habla con el teléfono) y el emulador.
Un Android donde correrUn emulador creado desde Android Studio, o mejor aún, su propio teléfono con depuración USB.

Requisitos de la máquina: Windows 10 u 11 de 64 bits, o macOS 13 o superior. 8 GB de RAM como mínimo (con 16 se trabaja cómodo). Unos 20 GB libres en disco. Usuario con permisos de administrador.

Windows: revisen el nombre de su usuario. Si la carpeta C:\Users\SuNombre tiene tilde, eñe o espacio (por ejemplo C:\Users\José Pérez), varias herramientas de Android fallan de formas raras. Escríbanme antes de instalar: la solución es poner el SDK en C:\Android\Sdk y se los explico.

Si usan Linux, también se puede; hablen conmigo y lo vemos aparte.

Windows 10 / 11

  1. Instalar Node.js LTS Abran PowerShell (clic derecho, "Ejecutar como administrador") y corran: 
    winget install OpenJS.NodeJS.LTS
    Si winget no existe en su máquina, descarguen el instalador LTS desde nodejs.org y acepten todo por defecto. Cierren y vuelvan a abrir la terminal, y verifiquen: 
    node -v
npm -v
    node -v debe mostrar v22.11 o superior.
  2. Instalar el JDK 17 (Microsoft Build of OpenJDK) 
    winget install Microsoft.OpenJDK.17
    Cierren la terminal, ábranla de nuevo y verifiquen que la versión sea 17: 
    java -version
    Si ya tenían otro Java instalado (por ejemplo el 21 o el 25 de otra materia), este paso no lo reemplaza. En ese caso, java -version puede seguir mostrando la otra versión; lo arreglamos con JAVA_HOME en el paso 4.
  3. Instalar Android Studio
    • Descarguen el instalador desde developer.android.com/studio y ejecútenlo.
    • En la pantalla de componentes dejen marcados Android Studio y Android Virtual Device. Siguiente hasta terminar.
    • Al abrirlo por primera vez elijan la instalación Standard y acepten las licencias. Va a descargar el SDK: paciencia.
    • En la pantalla de bienvenida: More Actions → SDK Manager.
    • Pestaña SDK Platforms: marquen la casilla Show Package Details (abajo a la derecha), desplieguen Android 15.0 ("VanillaIceCream") y marquen:
      • Android SDK Platform 35
      • Intel x86_64 Atom System Image o Google APIs Intel x86_64 Atom System Image (sirve también para procesadores AMD)
    • Pestaña SDK Tools: con Show Package Details activo, marquen:
      • Android SDK Build-Tools → la versión 36.0.0
      • Android SDK Command-line Tools (latest)
      • Android Emulator y Android SDK Platform-Tools (normalmente ya vienen marcados)
    • Clic en Apply y esperen la descarga.
  4. Configurar las variables de entorno Busquen en el menú Inicio "Editar las variables de entorno de la cuenta" (o: Panel de control → Cuentas de usuario → Cambiar mis variables de entorno). En la sección de arriba, Variables de usuario:
    • Nueva… → Nombre: ANDROID_HOME → Valor: %LOCALAPPDATA%\Android\Sdk
      (es la carpeta C:\Users\SuNombre\AppData\Local\Android\Sdk; si Android Studio les mostró otra ruta en el SDK Manager, usen esa).
    • Nueva… → Nombre: JAVA_HOME → Valor: la carpeta del JDK 17, normalmente C:\Program Files\Microsoft\jdk-17.0.x.x-hotspot (abran el Explorador y copien la ruta exacta; adentro tiene que haber una carpeta bin).
    • Seleccionen la variable Path → Editar… → Nuevo y agreguen estas dos líneas: 
      %LOCALAPPDATA%\Android\Sdk\platform-tools
%LOCALAPPDATA%\Android\Sdk\emulator
    • Aceptar en todas las ventanas. Cierren todas las terminales abiertas (las variables solo se cargan en terminales nuevas).
    Abran una terminal nueva y verifiquen: 
    echo %ANDROID_HOME%
echo %JAVA_HOME%
java -version
adb --version
    Las dos primeras deben mostrar las rutas, java -version debe decir 17 y adb debe mostrar una versión. Si alguna falla, revisen ese paso antes de seguir.
  5. Preparar dónde correr la app Sigan la sección Teléfono o emulador. Recomendación: si su laptop tiene 8 GB de RAM, vayan directo al teléfono.
  6. Verificar y entregar Sigan la sección Verificar y entregar.
Si PowerShell dice "la ejecución de scripts está deshabilitada" al correr npx, usen el Símbolo del sistema (cmd) en lugar de PowerShell, o corran una sola vez en PowerShell: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

macOS

  1. Instalar Homebrew (si no lo tienen) Abran la Terminal y verifiquen con brew -v. Si no existe, instálenlo con el comando oficial de brew.sh: 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    Al terminar, en una Mac con chip Apple (M1 a M4) el instalador muestra dos comandos bajo Next steps para agregar brew al PATH. Cópienlos y córranlos tal cual.
  2. Instalar Node.js y Watchman 
    brew install node watchman
node -v
    node -v debe mostrar v22.11 o superior. Watchman es un vigilante de archivos de Meta que hace que Fast Refresh sea más rápido.
  3. Instalar el JDK 17 (Azul Zulu) 
    brew install --cask zulu@17
    Después abran la carpeta donde quedó el instalador y ejecuten el .pkg: 
    open /opt/homebrew/Caskroom/zulu@17/
    (en Macs con Intel la ruta es /usr/local/Caskroom/zulu@17/). Entren a la carpeta con el número de versión y hagan doble clic en Double-Click to Install Azul Zulu JDK 17.pkg.
  4. Instalar Android Studio
    • Descarguen desde developer.android.com/studio la versión para su chip (Apple Silicon para M1 a M4, Intel para las demás). Si no saben cuál tienen: menú Apple → Acerca de esta Mac.
    • Arrastren Android Studio a Aplicaciones y ábranlo. Instalación Standard, acepten las licencias y esperen la descarga del SDK.
    • En la pantalla de bienvenida: More Actions → SDK Manager.
    • Pestaña SDK Platforms: marquen Show Package Details, desplieguen Android 15.0 ("VanillaIceCream") y marquen:
      • Android SDK Platform 35
      • Apple Silicon: Google APIs ARM 64 v8a System Image · Intel: Intel x86_64 Atom System Image
    • Pestaña SDK Tools: con Show Package Details activo, marquen Android SDK Build-Tools versión 36.0.0, Android SDK Command-line Tools (latest), Android Emulator y Android SDK Platform-Tools.
    • Apply y esperar.
  5. Configurar las variables de entorno Abran su archivo de perfil de la terminal. En macOS moderno es ~/.zshrc: 
    open -e ~/.zshrc
    (si dice que no existe, créenlo con touch ~/.zshrc y repitan). Agreguen al final estas líneas y guarden: 
    export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$PATH:$ANDROID_HOME/emulator
export PATH=$PATH:$ANDROID_HOME/platform-tools
    Cierren la Terminal, ábranla de nuevo y verifiquen: 
    echo $ANDROID_HOME
java -version
adb --version
    La primera debe mostrar la ruta del SDK, la segunda debe decir 17 y la tercera una versión de adb.
  6. Preparar dónde correr la app Sigan la sección Teléfono o emulador. En Macs con chip Apple el emulador corre muy bien.
  7. Verificar y entregar Sigan la sección Verificar y entregar.
¿Y Xcode? No hace falta para el módulo: iOS lo vamos a ver en demostración desde mi Mac. Si alguien quiere compilar para iPhone por su cuenta, necesita Xcode desde la App Store (unos 15 GB) y CocoaPods; lo vemos aparte.

Teléfono o emulador

Necesitan al menos uno de los dos. El teléfono es más rápido, consume menos recursos y es donde la app se va a usar de verdad; el emulador es cómodo cuando no tienen el cable a mano.

Opción A: su teléfono Android (recomendada)

  1. Activar las opciones de desarrollador Ajustes → Acerca del teléfono (o Información del software) → toquen siete veces sobre Número de compilación hasta que diga que ya son desarrolladores. En Xiaomi está en "Versión de MIUI/HyperOS"; en Samsung dentro de "Información de software".
  2. Activar la depuración USB Ajustes → Sistema → Opciones de desarrollador → Depuración USB: activar.
  3. Conectar y autorizar Conecten el teléfono con cable a la computadora. Si el teléfono pregunta el modo de conexión, elijan Transferencia de archivos. Aparece un aviso "¿Permitir depuración USB?": marquen Permitir siempre y acepten. En la terminal: 
    adb devices
    Debe aparecer su dispositivo con la palabra device. Si dice unauthorized, revisen el aviso en la pantalla del teléfono. Si no aparece nada, cambien de cable (muchos solo cargan) o de puerto; en Windows a veces hace falta el driver USB del fabricante (Samsung, Xiaomi, Huawei lo publican en su sitio).

Opción B: el emulador

  1. Crear el dispositivo virtual En Android Studio: More Actions → Virtual Device Manager → Create Virtual Device. Elijan un teléfono mediano (Pixel 7 o Medium Phone) → Next → en la lista de imágenes elijan VanillaIceCream, API 35 (la que instalaron en el SDK Manager) → Next → Finish.
  2. Arrancarlo Clic en el triángulo de Play. La primera vez tarda. Si arranca y ven el escritorio de Android, listo. Déjenlo abierto cuando vayan a correr la app.
  3. Si no arranca
    • Windows: la virtualización tiene que estar activa en el BIOS (VT-x en Intel, SVM en AMD). Además, en "Activar o desactivar las características de Windows" marquen Plataforma de hipervisor de Windows y reinicien.
    • Si la laptop tiene 8 GB de RAM, el emulador va a pelear con Android Studio y el navegador. Usen el teléfono.

Verificar y entregar

  1. Correr el doctor de React Native En una terminal nueva (importante, para que cargue las variables), corran: 
    npx @react-native-community/cli@latest doctor
    La primera vez pregunta si quieren instalar el paquete: respondan y. El doctor revisa Node, JDK, Android SDK, ANDROID_HOME y adb, y marca cada cosa con ✓ o ✖. Si ofrece arreglar algo (Press f to try to fix), pueden intentarlo.
  2. Tomar la captura Captura de pantalla de la terminal donde se vea el resultado completo del doctor. Las secciones de Common y Android deben estar en verde. Lo de iOS (Xcode, CocoaPods) va a salir en rojo o no aparecer en Windows: eso está bien, no lo necesitamos.
  3. Subirla al LMS antes del miércoles 11 a las 9 de la noche Si algo quedó en rojo y no lograron arreglarlo, suban la captura igual, con una línea diciendo en qué paso de esta guía se trabaron. Esa captura me sirve para llegar el jueves sabiendo exactamente a quién ayudar y con qué.
Con eso están listos. El jueves creamos el proyecto juntos, en clase. No instalen Expo, ni creen un proyecto todavía, ni instalen nada "por si acaso": vamos a hacerlo paso a paso para que entiendan cada carpeta que aparece.

Errores comunes

El doctor dice que no encuentra el Android SDK o ANDROID_HOME

Casi siempre es porque la terminal se abrió antes de configurar la variable, o porque la ruta tiene un error de escritura. Cierren todas las terminales, ábranla de nuevo y corran echo %ANDROID_HOME% (Windows) o echo $ANDROID_HOME (Mac). Abran esa ruta en el explorador: adentro debe haber una carpeta platform-tools.

java -version muestra 21, 25 u otra versión que no es 17

Tienen más de un Java. JAVA_HOME tiene que apuntar a la carpeta del 17 (ver el paso de variables de entorno de su sistema). En Windows, además, revisen que en Path no haya una entrada de otro Java antes que la del 17; si la hay, bájenla o quítenla.

"adb no se reconoce como un comando"

Falta platform-tools en el Path, o la terminal es vieja. Revisen el paso de variables y abran una terminal nueva.

El doctor pide una versión del SDK o de Build-Tools distinta a la de esta guía

Instálenla desde el SDK Manager tal como la pide (es cuestión de marcar la casilla y Apply). Las versiones de esta guía son las que piden las versiones actuales de React Native; cuando la herramienta pida otra, la herramienta gana.

El teléfono no aparece en adb devices

Cable que solo carga (cambien de cable), modo de conexión "Solo carga" (cambien a Transferencia de archivos), depuración USB apagada, o en Windows falta el driver del fabricante. Si dice unauthorized, acepten el aviso en el teléfono.

El emulador no arranca o dice algo de HAXM, Hyper-V o virtualización

Virtualización desactivada en el BIOS, o falta la "Plataforma de hipervisor de Windows". Mientras lo resuelven, usen el teléfono: para la clase es suficiente.

Nombre de usuario de Windows con tilde, eñe o espacio

Es el problema más incómodo porque los errores no dicen la causa. Escríbanme antes de seguir: movemos el SDK a C:\Android\Sdk desde el SDK Manager (Edit → Android SDK Location) y actualizamos ANDROID_HOME.

Antivirus o firewall

Algunos antivirus bloquean a Node cuando abre el puerto 8081 (Metro) o hacen lentísima la primera compilación de Gradle. Si Windows pregunta si permitir Node.js en redes privadas, digan que sí.

Si algo no está en esta lista, escríbanme con la captura del error exacto, su sistema operativo y el paso en el que estaban. "No me funciona" sin captura es un mensaje que no puedo resolver.
